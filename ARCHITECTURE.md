# NullSector Architecture Documentation

## Overview

NullSector is a task and reminder management iOS application built with SwiftUI and Supabase. The architecture follows a clean, layered approach: **MVVM + Repository + Service pattern**.

```
┌─────────────────────────────────────────────────────────┐
│                      SUPABASE                           │
│              (PostgreSQL Database)                      │
└─────────────────────────────────────────────────────────┘
                          ↑
                          │ Supabase Swift SDK
                          │
┌─────────────────────────────────────────────────────────┐
│                   REPOSITORY LAYER                      │
│          (TaskRepository, ReminderRepository)           │
│               Direct Database Access                    │
└─────────────────────────────────────────────────────────┘
                          ↑
                          │
┌─────────────────────────────────────────────────────────┐
│                    SERVICE LAYER                        │
│          (TaskService, ReminderService, etc.)           │
│        Business Logic, Validation, Filtering            │
└─────────────────────────────────────────────────────────┘
                          ↑
                          │
┌─────────────────────────────────────────────────────────┐
│                   VIEWMODEL LAYER                       │
│  (TaskListViewModel, ReminderListViewModel, etc.)       │
│         State Management, UI Logic                      │
└─────────────────────────────────────────────────────────┘
                          ↑
                          │
┌─────────────────────────────────────────────────────────┐
│                      VIEW LAYER                         │
│      (TaskListView, ReminderListView, etc.)             │
│              SwiftUI User Interface                     │
└─────────────────────────────────────────────────────────┘
```

## 1. Supabase Integration

### SupabaseClient.swift

```swift
@MainActor
class SupabaseClient {
    static let shared = SupabaseClient()
    let client: Client
    
    private init() {
        client = Client(
            supabaseURL: URL(string: Config.supabaseURL)!,
            supabaseKey: Config.supabaseAnonKey
        )
    }
}
```

**Key Concepts:**
- **@MainActor**: Ensures all Supabase operations run on the main thread (important for UI updates)
- **Singleton Pattern**: `static let shared` provides a single instance throughout the app
- **Client**: The Supabase client handles authentication, database queries, and real-time subscriptions

**How It Works:**
1. App launches → SupabaseClient.shared is initialized once
2. All repositories access the database through `SupabaseClient.shared.client`
3. Authentication state is managed through `client.auth`

## 2. Models Layer

### The Three-Struct Pattern

Each entity (Task, Reminder) uses three separate structs:

1. **Main Model** - Full data from database (includes `id`, `created_at`, `user_id`)
2. **Insert Model** - Data for creating new records (no `id`, `created_at`, `user_id`)
3. **Update Model** - Optional fields for partial updates

### Example: TodoTask.swift

```swift
// MAIN MODEL - Read from database
struct TodoTask: Identifiable, Codable, Hashable {
    let id: UUID
    let title: String
    let description: String?
    let dueDate: Date?
    let priority: Priority
    let isCompleted: Bool
    let createdAt: Date
    let userId: UUID
    
    enum CodingKeys: String, CodingKey {
        case id
        case title
        case description
        case dueDate = "due_date"        // Maps to snake_case
        case priority
        case isCompleted = "is_completed"
        case createdAt = "created_at"
        case userId = "user_id"
    }
}

// INSERT MODEL - Create new records
struct TodoTaskInsert: Codable {
    let title: String
    let description: String?
    let dueDate: Date?
    let priority: Priority
    
    enum CodingKeys: String, CodingKey {
        case title
        case description
        case dueDate = "due_date"
        case priority
    }
}

// UPDATE MODEL - Update existing records
struct TodoTaskUpdate: Codable {
    let title: String?
    let description: String?
    let dueDate: Date?
    let priority: Priority?
    let isCompleted: Bool?
    
    enum CodingKeys: String, CodingKey {
        case title
        case description
        case dueDate = "due_date"
        case priority
        case isCompleted = "is_completed"
    }
}
```

**Why This Pattern?**
- **Type Safety**: Prevents accidentally sending `id` or `created_at` during insert
- **Clear Intent**: Insert/Update models make it obvious what operation you're performing
- **Database Managed Fields**: `id`, `created_at`, `user_id` are auto-generated by Supabase
- **CodingKeys**: Maps Swift's `camelCase` to PostgreSQL's `snake_case`

### Reminder.swift with Recurrence

```swift
struct Reminder: Identifiable, Codable, Hashable {
    let id: UUID
    let taskId: UUID?
    let title: String
    let description: String?
    let remindAt: Date
    let isDismissed: Bool
    let recurrenceRule: RecurrenceRule?
    let createdAt: Date
    let userId: UUID
    
    enum CodingKeys: String, CodingKey {
        case id
        case taskId = "task_id"
        case title
        case description
        case remindAt = "remind_at"
        case isDismissed = "is_dismissed"
        case recurrenceRule = "recurrence_rule"
        case createdAt = "created_at"
        case userId = "user_id"
    }
}

enum RecurrenceRule: String, Codable, CaseIterable, Identifiable {
    case daily
    case weekly
    case monthly
    case yearly
    
    var id: String { rawValue }
    
    var displayName: String {
        switch self {
        case .daily: return "Daily"
        case .weekly: return "Weekly"
        case .monthly: return "Monthly"
        case .yearly: return "Yearly"
        }
    }
}
```

**Key Features:**
- **RecurrenceRule Enum**: Type-safe recurrence options
- **CaseIterable**: Automatically provides `allCases` for pickers
- **Identifiable**: Can be used directly in ForEach loops
- **displayName**: Human-readable labels for UI

## 3. Repository Layer

**Purpose**: Direct database access using Supabase query builder

### TaskRepository.swift

```swift
class TaskRepository {
    private let supabase = SupabaseClient.shared.client
    
    func fetchAll() async throws -> [TodoTask] {
        let response = try await supabase
            .from("tasks")
            .select()
            .order("created_at", ascending: false)
            .execute()
        
        return try JSONDecoder().decode([TodoTask].self, from: response.data)
    }
    
    func insert(_ task: TodoTaskInsert) async throws -> TodoTask {
        let response = try await supabase
            .from("tasks")
            .insert(task)
            .select()
            .single()
            .execute()
        
        return try JSONDecoder().decode(TodoTask.self, from: response.data)
    }
    
    func update(id: UUID, with updates: TodoTaskUpdate) async throws -> TodoTask {
        let response = try await supabase
            .from("tasks")
            .update(updates)
            .eq("id", value: id.uuidString)
            .select()
            .single()
            .execute()
        
        return try JSONDecoder().decode(TodoTask.self, from: response.data)
    }
    
    func delete(id: UUID) async throws {
        try await supabase
            .from("tasks")
            .delete()
            .eq("id", value: id.uuidString)
            .execute()
    }
}
```

### Supabase Query Builder Methods

| Method | Purpose | Example |
|--------|---------|---------|
| `.from("table")` | Select table | `.from("tasks")` |
| `.select()` | Fetch columns | `.select("id, title")` or `.select()` for all |
| `.insert(data)` | Create record | `.insert(TodoTaskInsert(...))` |
| `.update(data)` | Update record | `.update(TodoTaskUpdate(...))` |
| `.delete()` | Delete record | `.delete()` |
| `.eq("column", value:)` | WHERE clause | `.eq("id", value: "123")` |
| `.order("column")` | ORDER BY | `.order("created_at", ascending: false)` |
| `.single()` | Return single record | `.single()` (throws if 0 or 2+ results) |
| `.execute()` | Execute query | `.execute()` returns PostgrestResponse |

**Important Notes:**
- All repository methods use `async throws` for error handling
- `.select()` is required after `.insert()` or `.update()` to return the created/updated record
- `.single()` ensures exactly one record is returned (use for insert/update)
- UUIDs must be converted to strings: `id.uuidString`
- Row Level Security (RLS) policies automatically filter by authenticated user

## 4. Service Layer

**Purpose**: Business logic, validation, filtering, sorting

### TaskService.swift

```swift
class TaskService {
    private let repository = TaskRepository()
    
    func getTasks(
        showCompleted: Bool,
        searchQuery: String,
        sortBy: TaskSortOption
    ) async throws -> [TodoTask] {
        var tasks = try await repository.fetchAll()
        
        // Filter by completion
        if !showCompleted {
            tasks = tasks.filter { !$0.isCompleted }
        }
        
        // Search filter
        if !searchQuery.isEmpty {
            tasks = tasks.filter { task in
                task.title.localizedCaseInsensitiveContains(searchQuery) ||
                task.description?.localizedCaseInsensitiveContains(searchQuery) == true
            }
        }
        
        // Sort
        switch sortBy {
        case .dateCreated:
            tasks.sort { $0.createdAt > $1.createdAt }
        case .dueDate:
            tasks.sort { task1, task2 in
                guard let date1 = task1.dueDate else { return false }
                guard let date2 = task2.dueDate else { return true }
                return date1 < date2
            }
        case .priority:
            tasks.sort { $0.priority.rawValue > $1.priority.rawValue }
        }
        
        return tasks
    }
    
    func createTask(
        title: String,
        description: String?,
        dueDate: Date?,
        priority: Priority
    ) async throws -> TodoTask {
        // Validation
        guard !title.trimmingCharacters(in: .whitespaces).isEmpty else {
            throw TaskError.invalidTitle
        }
        
        let insert = TodoTaskInsert(
            title: title,
            description: description?.isEmpty == true ? nil : description,
            dueDate: dueDate,
            priority: priority
        )
        
        return try await repository.insert(insert)
    }
}
```

**Key Patterns:**
- **Filtering**: `filter { }` for conditional inclusion
- **Searching**: `localizedCaseInsensitiveContains` for case-insensitive search
- **Sorting**: `sort { }` with custom comparators
- **Validation**: Guard statements before database operations
- **Nil Handling**: Convert empty strings to `nil`

### ReminderService.swift - Recurring Logic

```swift
func dismissReminder(id: UUID) async throws {
    let reminder = try await repository.fetchById(id)
    
    // Mark current reminder as dismissed
    try await repository.update(
        id: id,
        with: ReminderUpdate(isDismissed: true)
    )
    
    // Create next occurrence if recurring
    if let rule = reminder.recurrenceRule {
        try await createNextRecurrence(for: reminder, rule: rule)
    }
}

private func createNextRecurrence(for reminder: Reminder, rule: RecurrenceRule) async throws {
    guard let nextDate = calculateNextOccurrence(from: reminder.remindAt, rule: rule) else {
        return
    }
    
    let insert = ReminderInsert(
        taskId: reminder.taskId,
        title: reminder.title,
        description: reminder.description,
        remindAt: nextDate,
        recurrenceRule: rule
    )
    
    try await repository.insert(insert)
}

private func calculateNextOccurrence(from date: Date, rule: RecurrenceRule) -> Date? {
    let calendar = Calendar.current
    
    switch rule {
    case .daily:
        return calendar.date(byAdding: .day, value: 1, to: date)
    case .weekly:
        return calendar.date(byAdding: .weekOfYear, value: 1, to: date)
    case .monthly:
        return calendar.date(byAdding: .month, value: 1, to: date)
    case .yearly:
        return calendar.date(byAdding: .year, value: 1, to: date)
    }
}
```

**How Recurring Reminders Work:**
1. User dismisses a reminder with a recurrence rule
2. Current reminder is marked `is_dismissed = true`
3. New reminder is automatically created with next date
4. Process repeats indefinitely until user deletes the recurring reminder

## 5. ViewModel Layer

**Purpose**: Manage UI state, coordinate service calls, handle user actions

### The @Observable Macro (iOS 17+)

```swift
@Observable
class TaskListViewModel {
    var tasks: [TodoTask] = []
    var isLoading = false
    var errorMessage: String?
    var showError = false
    
    // Form state
    var showingAddTask = false
    var showingEditTask = false
    var editingTask: TodoTask?
    
    // Filter state
    var searchQuery = ""
    var showCompleted = false
    var sortBy: TaskSortOption = .dateCreated
    
    // Delete state
    var taskToDelete: TodoTask?
    var showDeleteConfirmation = false
    
    private let taskService: TaskService
    
    init(taskService: TaskService = TaskService()) {
        self.taskService = taskService
    }
}
```

**@Observable Benefits:**
- Automatic UI updates when properties change
- No need for `@Published` or `ObservableObject`
- Cleaner syntax than Combine
- Works seamlessly with SwiftUI's `@State` and `@Binding`

### Data Fetching Pattern

```swift
func fetchTasks() {
    isLoading = true
    errorMessage = nil
    
    Task {
        defer { isLoading = false }  // Always runs, even if error thrown
        
        do {
            tasks = try await taskService.getTasks(
                showCompleted: showCompleted,
                searchQuery: searchQuery,
                sortBy: sortBy
            )
        } catch {
            errorMessage = error.localizedDescription
            showError = true
        }
    }
}
```

**defer Pattern:**
- `defer { }` always executes before leaving the scope
- Ensures `isLoading` is set to `false` even if an error occurs
- Prevents UI getting stuck in loading state

### Two-Step Delete Pattern

```swift
// Step 1: User requests delete
func requestDelete(task: TodoTask) {
    taskToDelete = task
    showDeleteConfirmation = true  // Shows confirmation dialog
}

// Step 2: User confirms
func confirmDelete() {
    guard let task = taskToDelete else { return }
    
    Task {
        do {
            try await taskService.deleteTask(id: task.id)
            
            // Remove from local array immediately
            if let index = tasks.firstIndex(where: { $0.id == task.id }) {
                tasks.remove(at: index)
            }
        } catch {
            errorMessage = error.localizedDescription
            showError = true
        }
    }
    
    // Reset state
    taskToDelete = nil
    showDeleteConfirmation = false
}
```

**Why Two Steps?**
- Prevents accidental deletions (especially with swipe actions)
- Gives users a chance to cancel
- Standard iOS pattern for destructive actions

### Array Updates

```swift
func toggleCompletion(for task: TodoTask) {
    Task {
        do {
            let updated = try await taskService.updateTask(
                id: task.id,
                with: TodoTaskUpdate(isCompleted: !task.isCompleted)
            )
            
            // Update local array
            if let index = tasks.firstIndex(where: { $0.id == task.id }) {
                tasks[index] = updated
            }
        } catch {
            errorMessage = error.localizedDescription
            showError = true
        }
    }
}
```

**Important**: Always update local arrays after successful database operations for instant UI feedback.

**HStack**:
- Horizontal arrangement of views

### LazyVStack - Performance for Long Lists

```swift
ScrollView {
    LazyVStack(spacing: 12) {
        ForEach(viewModel.tasks) { task in
            TaskRowView(task: task) {
                // Navigation
                viewModel.selectedTask = task
            }
        }
    }
    .padding()
}
```

**LazyVStack vs VStack:**
- **VStack**: Creates all views immediately (slow for 100+ items)
- **LazyVStack**: Creates views only when visible (fast for 1000+ items)
- Always use `LazyVStack` inside `ScrollView` for lists
- Must be inside a `ScrollView` to work

### Group - Conditional Rendering Without Layout

```swift

        ProgressView()

        emptyStateView
    } else {
        remindersList
    }
}
```

**Why Group?**
- Doesn't affect layout (unlike VStack/HStack)
- Allows conditional rendering in place
- Can apply modifiers to all children: `.padding()`, `.background()`

### ScrollView - Scrollable Content

```swift
ScrollView {

    }

```

**ScrollView Features:**
- Automatically scrollable when content exceeds screen
- `.refreshable`: Pull-to-refresh gesture
- Works with LazyVStack for performance

## 9. Custom Components

### Reusable Component Pattern

```swift
struct TaskRowView: View {
    let task: TodoTask
    let onTap: () -> Void
    let onToggleCompletion: () -> Void
    let onEdit: () -> Void
    let onDelete: () -> Void
    
    var body: some View {
        Button(action: onTap) {
            HStack(spacing: 12) {
                // Priority indicator
                Circle()
                    .fill(task.priority.color)
                    .frame(width: 8, height: 8)
                
                VStack(alignment: .leading, spacing: 4) {
                    Text(task.title)
                        .font(.headline)
                    
                    if let description = task.description {
                        Text(description)
                            .font(.subheadline)
                            .foregroundColor(.secondary)
                            .lineLimit(2)
                    }
                    
                    HStack {
                        PriorityBadgeView(priority: task.priority)
                        
                        if let dueDate = task.dueDate {
                            DueDateLabelView(dueDate: dueDate)
                        }
                    }
                }
                
                Spacer()
                
                if task.isCompleted {
                    Image(systemName: "checkmark.circle.fill")
                        .foregroundColor(.green)
                }
            }
            .padding()
            .background(Color(.systemBackground))
            .cornerRadius(12)
            .shadow(radius: 2)
        }
        .buttonStyle(PlainButtonStyle())
        .swipeActions(edge: .trailing) {
            Button(role: .destructive, action: onDelete) {
                Label("Delete", systemImage: "trash")
            }
            Button(action: onEdit) {
                Label("Edit", systemImage: "pencil")
            }
            .tint(.blue)
        }
        .swipeActions(edge: .leading) {
            Button(action: onToggleCompletion) {
                Label("Complete", systemImage: "checkmark")
            }
            .tint(.green)
        }
    }
}
```

**Callback Pattern:**
- Pass closures for actions: `() -> Void`
- Parent view handles business logic
- Component stays reusable and testable

**Usage:**

```swift
ForEach(viewModel.tasks) { task in
    TaskRowView(
        task: task,
        onTap: { viewModel.selectedTask = task },
        onToggleCompletion: { viewModel.toggleCompletion(for: task) },

        onDelete: { viewModel.requestDelete(task: task) }
    )
}
```

```swift
            .font(.subheadline)
            .foregroundColor(.secondary)
        
        TextField("Enter title", text: $viewModel.title)
            .textFieldStyle(RoundedBorderTextFieldStyle())
    }
    .padding()
    .background(Color(.systemBackground))
    .cornerRadius(12)
    .shadow(radius: 2)
    
    // Description Card
    VStack(alignment: .leading, spacing: 8) {
        Text("Description")
            .font(.subheadline)
            .foregroundColor(.secondary)
        
        TextEditor(text: $viewModel.description)
            .frame(height: 100)
            .padding(4)
            .background(Color(.systemGray6))
            .cornerRadius(8)
    }
    .padding()
    .background(Color(.systemBackground))
    .cornerRadius(12)
    .shadow(radius: 2)
    
    // Due Date Card
    VStack(alignment: .leading, spacing: 8) {
        Toggle("Set Due Date", isPresented: $viewModel.hasDueDate)
        
        if viewModel.hasDueDate {
            DatePicker(
                "Due Date",
                selection: $viewModel.dueDate,
                displayedComponents: [.date, .hourAndMinute]
            )
        }
    }
    .padding()
    .background(Color(.systemBackground))
    .cornerRadius(12)
    .shadow(radius: 2)
}
.padding()
```

**Form Design Principles:**
- Group related fields in cards
- Use `.background` + `.cornerRadius` + `.shadow` for depth
- Label above input for clarity
- Conditional fields with Toggle
- Consistent spacing and padding

### Create Flow

```
User Taps FAB

    ↓
Sheet Presented: TaskFormView
    ↓
User Fills Form & Taps Save
    ↓
ViewModel: createTask()
    ↓
Service: Validation + Business Logic
    ↓

    ↓
Database: Row Level Security Check + Insert
    ↓
Repository: Return Created Task
    ↓
Service: Return Task
    ↓
ViewModel: Add to tasks array
    ↓

```

### Update Flow

```
User Swipes Task → Edit
    ↓

    ↓
Sheet Presented: TaskFormView(mode: .edit)
    ↓
User Modifies & Taps Save
    ↓
ViewModel: updateTask(id:)
    ↓
Service: Validation
    ↓
Repository: Update in Supabase
    ↓
Database: RLS Check + Update
    ↓
Repository: Return Updated Task
    ↓
Service: Return Task
    ↓
ViewModel: Update tasks array at index
    ↓
View: Update UI + Dismiss Sheet
```

### Delete Flow

```
User Swipes Task → Delete
    ↓
View: requestDelete(task)
    ↓
ViewModel: taskToDelete = task, showDeleteConfirmation = true
    ↓
Confirmation Dialog Appears
    ↓
User Taps "Delete"
    ↓
ViewModel: confirmDelete()
    ↓
Service: deleteTask(id:)
    ↓
Repository: Delete from Supabase
    ↓
Database: RLS Check + Delete
    ↓
ViewModel: Remove from tasks array
    ↓
View: Update UI
```

### Filter/Search Flow

```
User Types in Search Bar

```

## Key Takeaways

### Architecture Benefits

1. **Separation of Concerns**: Each layer has a clear responsibility
2. **Testability**: Services and ViewModels can be unit tested
3. **Reusability**: Components are independent and composable
4. **Maintainability**: Changes are localized to specific layers
5. **Type Safety**: Swift's strong typing catches errors at compile time

### SwiftUI Patterns

1. **NavigationStack**: Modern navigation with type-safe destinations
2. **ZStack**: Layer UI elements (background, content, overlays)
3. **LazyVStack**: Performance for long lists
4. **Group**: Conditional rendering without layout
5. **@Observable**: Clean state management without Combine
6. **Bindings**: Two-way data flow with `$`
7. **defer**: Guaranteed cleanup in async operations
8. **Closures**: Callback pattern for reusable components

### Database Operations

1. **Three-Struct Pattern**: Separate models for read/insert/update
2. **Query Builder**: Fluent API for database operations
3. **Row Level Security**: Automatic user filtering
4. **CodingKeys**: Bridge Swift and SQL naming conventions
5. **async/await**: Modern concurrency for database calls

### Best Practices

1. **Validate in Service Layer**: Don't trust user input
2. **Update Local State Immediately**: Optimistic UI updates
3. **Two-Step Deletes**: Prevent accidental data loss
4. **Loading States**: Show feedback during async operations
5. **Error Handling**: Always catch and display errors
6. **Reusable Components**: Build once, use everywhere
7. **Consistent Spacing**: Use constants or design tokens
